# [US-008] Compress text files

> **Epic:** BP2 (see [EPIC-BP2-conventions.md](EPIC-BP2-conventions.md))
> **Rule:** `CompressTextFiles`, "Compresser les fichiers textuels", category `network`
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-006-014.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each page to report the HTML, CSS, JavaScript and SVG files transferred without compression, or with a weak algorithm,
**So that** the site owner can enable server compression and cut the transferred weight of text resources.

## 2. Context & Detailed Description

### Files checked

A request of the page is a text file when either:

- its response MIME type, without parameters, is `text/html`, `text/css`, `text/javascript`, `application/javascript`, `application/x-javascript`, `application/ecmascript` or `image/svg+xml`; or
- the MIME type is missing or generic, and its URL path ends with `.html`, `.htm`, `.css`, `.js`, `.mjs` or `.svg`.

### Exclusions

- **Small files.** Responses whose decoded size (`responseSize`) is **under 1 000 bytes** are excluded. This was a product decision: servers rightly skip compressing tiny files.
- Non-2xx responses, including `304`, are excluded.
- Responses without response headers in the recorded data cannot be judged and are excluded.

### Classification

The `content-encoding` response header is read case-insensitively. When it lists several encodings, the last one is the effective one.

| `content-encoding` | Classification |
|---|---|
| `br`, `gzip`, `x-gzip`, `zstd` | compressed |
| `deflate` | weak compression |
| absent, `identity` | **not compressed** |
| any other value | compressed, with the raw value shown in the detail |

### Grade

These follow the request; the worst grade wins.

- **C:** at least one file is not compressed.
- **B:** none uncompressed, but at least one uses `deflate`.
- **A:** all compressed with `br`, `gzip` or `zstd`, or there is no checked file: "Tous les fichiers textuels sont compressés".

### Offender lines

- Format: `<display name> (<type>, <size in ko>) : non compressé` or `… : compression faible (deflate)`.
- `<type>` is HTML, CSS, JS or SVG. The size is the decoded size.
- Uncompressed files come first, then by size, largest first.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** request headers already captured (`NetworkRequest.responseHeaders`, `type`, `responseSize`).
- **Out of scope:**
  - JSON, XML and plain text, though they could be added later;
  - estimating the gain in kB;
  - checking the compression level.
- **Data:** no infrastructure change is expected. The normaliser already keeps lower-cased response headers. The team lead should check that Firefox HAR entries expose `content-encoding`.
- **State:** synchronous.
- **Persistence:** stored with the page.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: all text files compressed
Given the page loaded "app.js" (40 kB, `content-encoding: br`) and "style.css" (12 kB, `content-encoding: gzip`)
When the best practices are evaluated
Then the rule is graded "A"

### Scenario 2: One uncompressed file gives C
Given the page loaded "vendor.js" (250 kB) with no `content-encoding` header
When the best practices are evaluated
Then the rule is graded "C"
And the line "vendor.js (JS, 250 ko) : non compressé" is listed

### Scenario 3: Deflate gives B
Given every text file is compressed and "legacy.css" (8 kB) uses `content-encoding: deflate`
When the best practices are evaluated
Then the rule is graded "B"
And the line "legacy.css (CSS, 8 ko) : compression faible (deflate)" is listed

### Scenario 4: C wins over B
Given one text file uses `deflate` and another has no compression
When the best practices are evaluated
Then the rule is graded "C"

### Scenario 5: zstd counts as good compression
Given "app.js" uses `content-encoding: zstd`
When the best practices are evaluated
Then it is compliant

### Scenario 6: Small files are ignored
Given "tiny.js" has a decoded size of 600 bytes and no compression
When the best practices are evaluated
Then it is not listed and does not affect the grade

### Scenario 7: Type detected from the extension when MIME is generic
Given "/assets/main.js" is served as `application/octet-stream`, uncompressed, 30 kB
When the best practices are evaluated
Then it is checked as JS and listed as "non compressé"

### Scenario 8: 304 responses and errors are ignored
Given "style.css" answered `304 Not Modified`, and "missing.js" answered `404`
When the best practices are evaluated
Then neither is checked

### Scenario 9: Header case and multiple encodings
Given a response header `Content-Encoding: GZIP`, and another response with `content-encoding: deflate, br`
When the best practices are evaluated
Then both are classified as compressed with a good algorithm

### Scenario 10: Page without text files in scope
Given a page whose text files are all under 1 kB
When the best practices are evaluated
Then the rule is graded "A" with the detail "Tous les fichiers textuels sont compressés"

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** `evaluate` is linear in the number of requests; 2 000 requests in under 10 ms.
- **Cross-browser:** identical results on Chrome and Firefox for the same headers.
