# [US-015] Preview a flagged image

> **Epic:** PV (see [EPIC-PV-conventions.md](EPIC-PV-conventions.md))
> **Depends on:** US-004 (names), US-005 (comparison dialog, reused), US-006, US-007, US-013 (rules)
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-015-018.md`)

## 1. User Story Statement

**As an** eco-design and accessibility auditor,
**I want to** click the name of an image flagged for a missing alternative, eager loading or GIF use, and see the image with its resolution, format and weight,
**So that** I can identify it at a glance on the page and judge the issue (is it decorative? is this GIF worth 900 kB?) without searching the DOM.

## 2. Context & Detailed Description

### Where the name is clickable

| Rule | Lines |
|---|---|
| "Fournir une alternative textuelle aux contenus multimédias" (US-006) | `<img>` and `<input type="image">` lines, both "alternative absente" and "alternative vide" |
| "Utiliser le chargement paresseux" (US-007) | image lines. Iframe lines are covered by US-017 |
| "Limiter l'utilisation des GIFs animés" (US-013) | every GIF line |

The epic §1 exclusions apply: `<area>`, "(sans source)", and non-`http(s)` URLs stay plain text.

### Modal content

- The header follows epic §3.
- **The image itself.** It is displayed with the browser's own decoder from the file bytes, so every format the browser can display works: JPEG, PNG, WebP, AVIF, **GIF (animated GIFs play)**, SVG, BMP and ICO. An SVG is displayed as an image, so its scripts never run.
- **Information:**
  - **Résolution:** `1200 × 800 px`, read from the file. For an SVG without intrinsic size: "non définie (image vectorielle)".
  - **Format:** `JPEG`, `PNG`, `WebP`, `AVIF`, `GIF`, `GIF animé`, `SVG`, `BMP`, `ICO`; "inconnu" otherwise. It is detected from the bytes, else from the MIME type.
  - **Poids:** the byte length of the file obtained, for example `45 ko`.
- **No toggle:** there is a single version, the original. The optimised versions remain a feature of the image rules (US-005).

### Display modes

These are the same as US-005, with the same texts.

- **Default: "Même taille que sur la page".**
  - The image is drawn in its CSS display box on the page, scaled down proportionally if wider than the modal.
  - The box comes from the page at the latest collection: the flagged element itself for US-006 and US-007, and the largest `<img>` showing that URL for US-013.
- **"Taille réelle" checkbox:** 1 image pixel = 1 physical screen pixel (natural size ÷ `devicePixelRatio`), and the area scrolls.
- **Not displayed** (0 × 0 box, GIF only used as a CSS background or loaded by a script, or unknown box in an older analysis): the modal opens in "Taille réelle" with the hint "Image non affichée sur la page". The checkbox is then checked and disabled.

### States

- `loading`: "Chargement…".
- `error`:
  - "Image indisponible." when the bytes cannot be obtained (404, network, not an image);
  - "Image trop volumineuse pour l'aperçu." when the file is over 25 MB (PO default);
  - "Ce format d'image ne peut pas être affiché." when the browser fails to decode it.
  - Each has a "Réessayer" button.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:**
  - clickable names in the three rules;
  - the preview content;
  - display boxes collected for those images;
  - GIF and SVG support in the preview path.
- **Out of scope:**
  - optimised variants;
  - editing or suggesting an alternative text;
  - CSS background images of US-006 and US-007 (not in those rules);
  - frame-by-frame GIF controls.
- **Hints for the team lead (not decisions):**
  - The US-005 dialog, its controller and the variant store are designed for this. A preview is a subject with only the original version.
  - The codec worker's `inspect` refuses GIF, SVG, BMP and ICO, because it only accepts formats the codecs can re-encode. The preview needs a path that accepts any image format, reading the size from the header (GIF) or from the browser's decoded image.
  - US-006 and US-007 collectors must add the CSS box of each element, with at most one `getBoundingClientRect` per element; the US-006 and US-007 budgets still hold. US-013 has no collector yet.
- **Persistence:** the display boxes are stored with the page, optional. The bytes are never stored.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: preview an image without alternative
Given the rule "Fournir une alternative textuelle aux contenus multimédias" lists "hero.jpg : alternative absente"
And hero.jpg is 1200 × 800 px, 180 ko, displayed at 600 × 400 on the page
When the auditor clicks "hero.jpg"
Then a modal opens titled "hero.jpg" with the full URL under the title
And it shows "1200 × 800 px", "JPEG" and "180 ko"
And the image is drawn at 600 × 400 ("Même taille que sur la page")

### Scenario 2: Real size
Given the modal of scenario 1 on a panel with devicePixelRatio 2
When the auditor checks "Taille réelle"
Then the image is drawn at 600 × 400 CSS pixels (1200 × 800 physical pixels) in a scrollable area

### Scenario 3: Animated GIF from the GIF rule
Given the rule "Limiter l'utilisation des GIFs animés" lists "anim.gif : 900 ko"
When the auditor clicks "anim.gif"
Then the modal shows the GIF playing, with format "GIF animé" and weight "900 ko"

### Scenario 4: GIF not displayed by an img element
Given "loader.gif" is only used as a CSS background on the page
When the auditor opens its preview
Then the modal opens in "Taille réelle" with the hint "Image non affichée sur la page"
And the checkbox is checked and disabled

### Scenario 5: Image below the fold from the lazy-loading rule
Given "Utiliser le chargement paresseux" lists "photo.webp : chargée immédiatement (située à 1 500 px du haut de page)"
When the auditor clicks "photo.webp"
Then the preview modal opens for photo.webp with its resolution, "WebP" and its weight

### Scenario 6: SVG image
Given an image line names "logo.svg", an SVG without width and height attributes
When the auditor opens its preview
Then the SVG is displayed, its scripts do not run
And the resolution is "non définie (image vectorielle)"

### Scenario 7: Lines that are not clickable
Given US-006 lists "(sans source) : alternative absente", an `<area>` line, and an image whose URL is `data:…`
When the auditor views the lines
Then none of these names is a button

### Scenario 8: Image unavailable, then retry
Given the image of a line returns 404 and DevTools has no content for it
When the auditor opens its preview
Then the modal shows "Image indisponible." and a "Réessayer" button
When the image becomes available and the auditor clicks "Réessayer"
Then the image and its information are displayed

### Scenario 9: Image too large
Given a GIF of 40 MB
When the auditor opens its preview
Then the modal shows "Image trop volumineuse pour l'aperçu." and nothing is decoded

### Scenario 10: Reopening is instant
Given the auditor already opened the preview of hero.jpg in this panel session
When they open it again
Then the image is shown without the "Chargement…" state

### Scenario 11: Saved analysis
Given a saved analysis whose US-013 lines list "anim.gif"
When the auditor opens the analysis and clicks "anim.gif"
Then the preview works, from DevTools content or the HTTP cache

### Scenario 12: Close and late result
Given the preview of a large image is loading
When the auditor presses Escape
Then the modal closes and focus returns to the "hero.jpg" button
And the late result creates no object URL and changes nothing on screen

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** the modal opens (loading state visible) in under 100 ms. A cached image is shown immediately. The collectors keep the budgets of US-006 (2 000 elements < 50 ms) and US-007.
- **Accessibility:**
  - native `<dialog>`, focus management as in epic §2;
  - the image has an `alt` such as "Aperçu de hero.jpg, 1200 × 800 px, 180 ko";
  - "Taille réelle" is a checkbox with a visible label;
  - loading uses `role="status"` and errors `role="alert"`.
- **Security:** SVG is displayed through `<img>` from a `blob:` URL, never inlined into the DOM.
- **Sobriety:** a file is read once per panel session (cache), and only when the auditor asks for it.
