# [US-020] Preview a non-minified text file

> **Epic:** PV (see [EPIC-PV-conventions.md](EPIC-PV-conventions.md))
> **Depends on:** US-010 (`MinifyTextFiles`, "Minifier les fichiers CSS, JavaScript, HTML et SVG"), US-004 (names); shares the preview dialog with US-015 to US-018
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-019-020.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want to** click a file flagged as not minified and read its content, with syntax colouring,
**So that** I can show the site owner the comments, indentation and blank lines that minification would remove, without leaving the panel.

## 2. Context & Detailed Description

### Clickable lines (change to US-010)

This is an owner decision.

- Only the **offender lines** are clickable: `<name> (<type>, <weight>) : non minifié (~N % d'octets superflus)`. Their shortened name becomes the preview button of epic §1.
- Lines `… : non évalué (<reason>)` stay **plain text**.
- "… et N autres" is plain text.
- Only `http(s)` URLs are clickable (epic §1).
- The line text, sort order, grade and detail of US-010 are **unchanged**.
- **Analyses saved before this story:** their offender lines already carry a file reference (`lineRefs`), so they are clickable too (epic §6). Their "non évalué" lines stay plain text.

### Modal content

- **Header** (epic §3): the shortened file name as the title, with the full name in `title` and for screen readers. Under it is the full URL: selectable, wrapping, never truncated.
- **Information** (epic §4):
  - **Type:** `CSS`, `JavaScript`, `HTML` or `SVG`, the type of the line.
  - **Poids:** the byte length of the content obtained, through `formatKo`, for example `48 ko`.
  - **Lignes:** the number of lines of the whole content, in French number format, for example `1 234`.
- **Content:**
  - The text, **exactly as obtained**, is shown in a monospace block under the information list. It is never reformatted or pretty-printed.
  - **Line numbers** are shown in a gutter. They are not selected or copied with the text.
  - **Long lines wrap** inside the modal; there is no horizontal scroll. Wrapped lines keep a single line number.
  - The block scrolls vertically inside the modal; the header and information list stay visible.
- **Syntax colouring** (best effort):
  - **JavaScript** (`JS` lines), **CSS**, **HTML**, and **SVG** coloured as markup (HTML / XML). **JSON** is also supported by the viewer, for future rules, even though US-010 never flags JSON files.
  - The language comes from the line's type, which is the same detection as US-010.
  - Tokens coloured at minimum: comments, strings, numbers, keywords (JS), tag names, attribute names and attribute values (HTML/SVG), selectors, properties and values (CSS), keys and literals (JSON).
  - Comments must be clearly distinguishable, because they are what the auditor wants to point at.
  - Colours follow the panel's light and dark themes and keep a text contrast of at least 4.5:1.
  - Colouring is **never blocking**: if it fails or the language is unknown, the content is shown as plain text, without an error.
- **Display limit** (owner decision):
  - Only the **first 500 000 characters** are displayed.
  - When the content is longer, a notice is shown above the block: `Affichage limité aux 500 premiers ko (fichier de 1 234 ko).`
  - **Poids** and **Lignes** always describe the whole file.

### Content source

This is an owner decision; epic §5 applies.

- The content comes from what **DevTools captured** for the page. Otherwise it is **re-downloaded from the HTTP cache when possible**, exactly as the other previews do.
  - This does not change US-010: the **grade** still uses DevTools content only. Re-downloading is only for display.
- It is decoded with the `charset` of the response `content-type`, else UTF-8. Invalid bytes show as `�`; this is not an error.
- The re-downloaded content may differ from the analysed version, for example after a site deployment. This is accepted and is not detected.
- Nothing is persisted, and nothing is sent to a third party. Contents are kept in the panel session's shared preview cache (50 MB LRU), so reopening a file is instant.

### Safety

- The content is **always displayed as text**. HTML, SVG and JS from the file are **never interpreted, executed or rendered**: no script runs, no link or image loads, and no style applies to the panel.
- This holds even with hostile content, such as `</pre><script>`, `<img onerror>` or `<style>` inside a comment.

### States (epic §7)

- `idle`: before opening.
- `loading`: `Chargement du fichier…`, with `role="status"`.
- `loaded`: information, then the content.
- `error`, each with a `Réessayer` button and `role="alert"`:
  - `Fichier indisponible.`: no DevTools content and the re-download failed;
  - `Fichier trop volumineux pour être affiché.`: over the 25 MB preview cap. US-010 never flags such a file, so this is a safeguard.
- An **empty** content is `loaded`, with `Fichier vide.` in place of the block.
- A late result after the modal closed is ignored.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:**
  - the preview reference on US-010 offender lines;
  - the text preview body (header, information, colouring, cap, states);
  - the text loading path through the existing preview loader and store;
  - the colouring for JS, JSON, HTML / SVG and CSS.
- **Out of scope:**
  - a pretty-printer or "Formater" button;
  - search in the content;
  - a copy button (native selection works);
  - highlighting *which* bytes are removable;
  - previews from the other text rules, such as US-008 compression. A later story may reuse this body;
  - a source-map lookup.
- **Hints for the team lead:**
  - Colouring library or in-house tokenizer is the team lead's choice, with these constraints:
    - it is **bundled**: no CDN, no network;
    - it has a permissive licence (MIT, BSD or Apache);
    - it works under the current extension CSP **without adding** `default-src`, `style-src` relaxations, `eval` or `new Function`;
    - it is preferably lazy-loaded with the body, so it adds nothing to the panel's initial load.
  - The output must be built from **escaped text nodes or spans**, never from `innerHTML` of file content. If a library returns HTML, it must be one that escapes the input, and that escaping must be tested with hostile fixtures.
  - The 500 000-character cap keeps colouring tractable. If a 500 ko file still blocks the panel for too long, colouring may be chunked or moved to a worker. The plain text is shown first, and colours are applied after.
  - `MAX_CONTENT_BYTES`, the 5 MB analysis cap, is unrelated to the display cap. Keep both constants in their policy files.
- **Persistence:** only the `preview` of the offender lines' `lineRefs` (ARCH-DECISION-017/020). File contents are never stored.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path, open a non-minified CSS file
Given "Minifier les fichiers CSS, JavaScript, HTML et SVG" lists "main.css (CSS, 48 ko) : non minifié (~23 % d'octets superflus)"
When the auditor clicks "main.css"
Then a modal opens titled "main.css", with the full URL under it
And it shows "Type : CSS", "Poids : 48 ko" and the number of lines
And the content is displayed with line numbers, its comments, selectors, properties and values coloured

### Scenario 2: JavaScript and HTML colouring
Given the offender lines "app.js (JS, …)" and "index.html (HTML, …)"
When the auditor opens each of them
Then "app.js" is coloured as JavaScript: keywords, strings, numbers and comments
And "index.html" is coloured as markup: tag names, attribute names and values, and comments

### Scenario 3: SVG is coloured as markup
Given the offender line "logo.svg (SVG, 12 ko) : non minifié (…)"
When the auditor opens it
Then "Type : SVG" is shown and the content is coloured as markup
And the SVG is not rendered as an image

### Scenario 4: Non-evaluated lines are not clickable
Given the line "big.js (JS, 6 000 ko) : non évalué (fichier trop volumineux)"
When the best-practice lines are displayed
Then "big.js" is plain text, not a button

### Scenario 5: Content not captured by DevTools, re-downloaded from the cache
Given DevTools has no content for "main.css" and the file is in the HTTP cache
When the auditor opens its preview
Then the content is displayed from the cached copy

### Scenario 6: File unavailable, then retry
Given DevTools has no content for "main.css" and the re-download fails
When the auditor opens its preview
Then "Fichier indisponible." is shown with role "alert" and a "Réessayer" button
When the file becomes reachable and the auditor clicks "Réessayer"
Then the content is displayed

### Scenario 7: Display cap
Given a non-minified "bundle.js" of 1 234 000 characters
When the auditor opens its preview
Then only the first 500 000 characters are displayed
And the notice "Affichage limité aux 500 premiers ko (fichier de 1 234 ko)." is shown above the content
And "Poids" and "Lignes" describe the whole file

### Scenario 8: Hostile content is never interpreted
Given an HTML offender whose content contains `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>` and `</pre><style>body{display:none}</style>`
When the auditor opens its preview
Then that markup is displayed as text
And no script runs, no request is made for "x", and the panel's styles are unchanged

### Scenario 9: Long single line wraps
Given an offender whose content is one 80 000-character line
When the auditor opens its preview
Then the line wraps inside the modal with the single line number "1"
And there is no horizontal scrollbar

### Scenario 10: Colouring failure falls back to plain text
Given the colouring of a file fails or its language is unknown
When the auditor opens its preview
Then the content is displayed as plain text with line numbers, without an error message

### Scenario 11: Charset
Given "legacy.css" is served with `content-type: text/css; charset=iso-8859-1` and contains "é"
When the auditor opens its preview
Then "é" is displayed correctly

### Scenario 12: Legacy analysis
Given an analysis saved before this story, with an offender line and a "non évalué" line of this rule
When the auditor opens it
Then the offender's name is clickable and opens the text preview
And the "non évalué" line stays plain text

### Scenario 13: Close while loading
Given the content is loading
When the auditor closes the modal
Then the late result is ignored, and reopening the file uses the cached content once loaded

### Scenario 14: Empty content
Given the content obtained for the file is empty
When the auditor opens its preview
Then "Fichier vide." is shown in place of the content block, with "Poids : 0 ko"

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:**
  - The plain text of a 500 ko file is visible within **300 ms** after the bytes are available.
  - Colouring must not freeze the panel for more than **100 ms** at a time.
  - Reopening a cached file is immediate.
  - The colouring code is not loaded until the first text preview opens (preferred).
- **Accessibility:**
  - Focus management follows epic §2.
  - The content block is a scrollable region reachable with Tab (`tabindex="0"`), labelled `Contenu du fichier`.
  - Line numbers are hidden from screen readers and excluded from selection.
  - Colours are not the only cue; the text stays readable without them.
  - Errors use `role="alert"`; loading uses `role="status"`.
- **Security:** the file content is displayed as text only; see §2 Safety and scenario 8.
- **Isolation:** no CSP change; `scripts/manifest.test.mjs` keeps passing.
