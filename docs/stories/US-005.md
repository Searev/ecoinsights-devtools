# [US-005] Compare an image with its optimised version

> **Epic:** Image comparison (US-004 → US-005)
> **Depends on:** US-004 (image name element), plus the estimation pipeline of US-001 to US-003 (ARCH-DECISION-007 to 011)
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-004-005.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want to** open an offending image and toggle between its original and optimised versions, seeing the resolution and weight of each,
**So that** I can check that the optimisation keeps an acceptable visual quality, and convince the site owner with a concrete before/after.

## 2. Context & Detailed Description

The image rules estimate gains, but nobody can *see* what the optimised image looks like. A gain of 144 kB is only convincing if the AVIF at quality 65 looks the same as the JPEG.

### Trigger

- In both image rules, the image name of every **offender** line (US-004) becomes a `<button>`. Clicking it, or pressing Enter or Space, opens the comparison dialog.
- Lines that aren't offenders (not evaluated, skipped, gain under the noise threshold, still estimating) show the name as plain text, not clickable.

### Which optimised version

These are product decisions.

| Clicked from | Toggle options |
|---|---|
| "Ne pas redimensionner les images dans le navigateur" | **Originale** / **Redimensionnée** (target size, same format) |
| "Utiliser des formats d'image optimisés" | **Originale** / **AVIF** (JPEG source, q65) or **WebP sans perte** (PNG source) |
| An image that is an offender of **both** rules, from either list | the two options above plus **Les deux** (resized and converted, the variant used for the page gain) |

**Originale** is selected when the dialog opens.

### Information shown for the selected version

- Resolution, for example `1200 × 800 px`.
- File size in French format, for example `240 ko`.
- Format: `JPEG`, `PNG`, `WebP`, `WebP sans perte` or `AVIF`.
- For an optimised version, the gain: `−144 ko (−60 %)`.
- The dialog header shows the US-004 display name and, under it, the **full URL**. The URL is selectable text that wraps and is never truncated.

### Display modes

- **Default: "Même taille que sur la page".**
  - Every version is drawn in the same box: the image's CSS display size on the page, taken from the finding, scaled down proportionally if it is wider than the dialog. The toggle then shows exactly what a visitor would see.
  - When the image was not displayed on the page (CSS size 0 × 0, possible for the format rule), this mode is unavailable. The dialog opens in "Taille réelle" with the hint "Image non affichée sur la page".
- **"Taille réelle" switch.**
  - Each version is drawn at its native resolution: 1 image pixel = 1 physical screen pixel, so the CSS size is the natural size ÷ the panel's `devicePixelRatio`.
  - The image area scrolls, and toggling keeps the scroll position, so compression artefacts can be inspected on the same spot.
  - A resized version therefore looks smaller here, as expected.

### On-demand generation

- Optimised bytes are not stored, so the dialog **generates the selected variant on demand** when it opens. It reuses the existing codec worker and the same encoding settings, so sizes match the estimates.
- Generated variants are cached in memory for the panel session. Reopening the same image is instant.
- **Original bytes** come from DevTools content when available, else a re-download from the HTTP cache when possible. This is already allowed by the README privacy section.
- It works on a **recording in progress and on saved analyses**.

### States per version

These are explicit:

- `loading`: the area shows "Génération de la version optimisée…" or "Chargement de l'image originale…" (`role="status"`).
- `loaded`: the image and its information.
- `error`: one of the messages below, with a **"Réessayer"** button that only retries that version.

| Cause | Message |
|---|---|
| Original bytes unavailable (404, network) | "Image originale indisponible." |
| Encoding failed | "La version optimisée n'a pas pu être générée." |
| Browser cannot display the result (`<img>` load error) | "Votre navigateur ne peut pas afficher ce format." |

The toggle stays usable while a version loads. Selecting a loading version shows its loading state.

### Image changed since the analysis

If the re-downloaded original's size differs from the size recorded in the analysis, show the notice "L'image a changé depuis l'analyse : les tailles affichées peuvent différer de l'estimation." The figures shown are those of the current bytes.

### Closing

- The dialog closes with the close button, Escape, or a click on the backdrop.
- Focus returns to the image name that opened it.
- Generation still running when the dialog closes completes in the background and fills the cache, with no UI update. Object URLs are revoked on close.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:**
  - the clickable names (offenders only);
  - the modal dialog;
  - the toggle with 2 or 3 options;
  - the information block;
  - the two display modes;
  - on-demand generation reusing the codec worker and the `ImageEstimator` pipeline;
  - the in-memory variant cache;
  - the loading, loaded and error states with retry;
  - the "image changed" notice.
- **Out of scope:**
  - a side-by-side or slider comparison;
  - downloading the optimised file;
  - visual-quality metrics (SSIM, PSNR);
  - comparing a whole page;
  - persisting optimised bytes;
  - the CSV export.
- **Architecture hints for the team lead (not decisions):**
  - The current worker protocol returns sizes only. It needs a way to return the **encoded bytes** of one variant on request, without changing the estimation path or making it slower.
  - Keep a session cache with a memory cap and LRU eviction, for example 50 MB; that number is the PO's default.
  - Displaying AVIF and WebP from a `Blob` URL works in Chrome ≥ 103 and Firefox ≥ 109. Check that the extension page CSP allows `blob:` images (`img-src`).
  - The finding must carry what the dialog needs: URL, natural size, CSS display size, target size, source format and recorded original size. Check `ImageFinding` and extend it in a backward-compatible way if needed.
- **State:** dialog-local. Per version, `idle | loading | loaded | error`, plus the selected version and the display mode. Nothing global, nothing persisted.
- **Persistence:** none.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: resize rule, toggle original and resized
Given the resize rule lists "photo.jpg" as an offender: natural size 1200×800, displayed at 300×200 CSS px on a 2x screen, target 600×400, original 240 kB
When the auditor clicks "photo.jpg"
Then a modal dialog opens with "Originale" selected, showing "1200 × 800 px", "240 ko" and "JPEG"
And both versions are drawn in a 300×200 box
When the auditor selects "Redimensionnée"
Then the dialog shows "Génération de la version optimisée…" until the variant is generated
And then shows "600 × 400 px", its size in ko, "JPEG" and the gain "−… ko (−… %)"

### Scenario 2: Format rule, JPEG to AVIF
Given the format rule lists "photo.jpg" (JPEG, 240 kB) as an offender
When the auditor opens it and selects "AVIF"
Then the dialog shows the AVIF version with "1200 × 800 px", "AVIF" and the gain against 240 kB

### Scenario 3: Image flagged by both rules
Given "photo.jpg" is an offender of both image rules
When the auditor opens it from either list
Then the toggle offers "Originale", "Redimensionnée", "AVIF" and "Les deux"
And "Les deux" shows the resized and converted version, whose size matches the combined estimate used for the page gain

### Scenario 4: Sizes match the estimates
Given the original bytes are the ones analysed
When a variant is generated in the dialog
Then its size equals the size estimated for that image and transformation in the best-practice line

### Scenario 5: Native size mode
Given the comparison dialog is open in "Même taille que sur la page"
When the auditor enables "Taille réelle" on a panel with devicePixelRatio 2
Then the original 1200×800 is drawn at 600×400 CSS px and the resized 600×400 at 300×200 CSS px
And toggling between versions keeps the scroll position of the image area

### Scenario 6: Image not displayed on the page
Given the format rule lists "hidden.png", displayed at 0×0 on the page
When the auditor opens it
Then the dialog opens in "Taille réelle"
And the "Même taille que sur la page" mode is unavailable with the hint "Image non affichée sur la page"

### Scenario 7: Saved analysis
Given a saved analysis whose image bytes are not in memory
When the auditor opens an offender
Then the original is re-downloaded and the variant generated on demand
And the comparison works as on a recording

### Scenario 8: Second opening is instant
Given the auditor already generated the "AVIF" version of "photo.jpg" in this panel session
When they close the dialog and open it again and select "AVIF"
Then the version is displayed without a new encoding

### Scenario 9: Original unavailable
Given the original image of an offender now returns HTTP 404 and its bytes are not in memory
When the auditor opens it
Then the "Originale" area shows "Image originale indisponible." with a "Réessayer" button
And the optimised versions show the same error, since they cannot be generated without the original

### Scenario 10: Encoding failure and retry
Given the generation of the "AVIF" version fails
When the auditor selects "AVIF"
Then it shows "La version optimisée n'a pas pu être générée." and a "Réessayer" button
And "Originale" remains displayed normally when selected
When the auditor clicks "Réessayer" and the generation succeeds
Then the AVIF version is displayed

### Scenario 11: Image changed since the analysis
Given the analysis recorded "photo.jpg" at 240 kB
And the re-downloaded original now weighs 180 kB
When the auditor opens it
Then the notice "L'image a changé depuis l'analyse : les tailles affichées peuvent différer de l'estimation." is shown
And the figures are computed from the 180 kB original

### Scenario 12: Non-offender lines are not clickable
Given an image line that is "non évaluée", still estimating, or under the 10 kB noise threshold
When the auditor clicks its name
Then no dialog opens
And the name is not rendered as a button

### Scenario 13: Closing and focus return
Given the comparison dialog is open from the "photo.jpg" button
When the auditor presses Escape, clicks the close button, or clicks the backdrop
Then the dialog closes
And keyboard focus returns to the "photo.jpg" button

### Scenario 14: Closing during generation
Given the "Les deux" version is being generated
When the auditor closes the dialog
Then no error is shown
And reopening the image later shows the version from the cache once the generation has completed

### Scenario 15: Rapid double click
Given an offender line
When the auditor double-clicks its name quickly
Then exactly one dialog opens

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Responsiveness:**
  - The dialog opens within 100 ms, with loaders if bytes or variants are not ready.
  - Encoding stays in the worker, and no main-thread task over 50 ms is caused by the dialog.
- **Sobriety:**
  - Generate only the selected variant, never all variants up front.
  - The session cache is capped (PO default 50 MB, LRU).
  - Object URLs are revoked on close.
  - Dialog generation never delays the estimation queue of a recording in progress, beyond sharing the single worker.
- **Accessibility:**
  - native `<dialog>` opened with `showModal()`, labelled by its title (`aria-labelledby`), with focus trapped inside;
  - the toggle is a radio group, navigable with the arrow keys;
  - "Taille réelle" is a checkbox or switch with a visible label;
  - each image has an `alt` such as "Version AVIF de photo.jpg, 1200 × 800 px, 96 ko";
  - loading states use `role="status"` and errors use `role="alert"`.
- **Privacy:** re-downloads follow the README's "Vie privée" section. Nothing is sent to any third party.
- **Cross-browser:** identical behaviour on Chrome ≥ 103 and Firefox ≥ 109.
