# [US-017] Show the data of a flagged iframe

> **Epic:** PV (see [EPIC-PV-conventions.md](EPIC-PV-conventions.md))
> **Depends on:** US-007 (rule); shares the preview dialog with US-015
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-015-018.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want to** click the name of an iframe flagged by the lazy-loading rule and see its data,
**So that** I can identify the embedded content (a map, a video player, an ad) and its cost without opening it.

## 2. Context & Detailed Description

### Where the name is clickable

In "Utiliser le chargement paresseux" (US-007), the lines "Iframe `<name>` : chargée immédiatement (située à `<n>` px du haut de page)". The prefix "Iframe " stays plain text.

### Modal content

This is a **product decision: data only, no embedded content.** Embedding an arbitrary third-party page inside the extension is a security risk, and many sites refuse to be framed.

- The header follows epic §3: the shortened name, then the full URL.
- **Information:**
  - **Hôte:** the host name of the URL, for example `www.google.com`.
  - **Type:** the recorded MIME type of the iframe document, for example `text/html`; "inconnu" when not recorded.
  - **Poids transféré:** the transferred bytes of the iframe document request recorded for the page, for example `48 ko`; "non mesuré" when not recorded. Only the document is counted, not its sub-resources.
  - **Position:** "à 1 500 px du haut de page", from the US-007 data.
- No image, no "Taille réelle", and no loading state: the data is already in the analysis, so the content is `loaded` on open.
- A button **"Ouvrir dans un nouvel onglet"** is **not** part of this story.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** clickable iframe names in US-007, and the data modal.
- **Out of scope:**
  - rendering the iframe;
  - listing the iframe's sub-resources;
  - other rules.
- **Data:**
  - The document request is found among the page's recorded requests by URL, ignoring the fragment.
  - The position is the one shown in the line; the team lead decides whether it is persisted structurally or read from the finding.
- **Persistence:** no new persisted data is required, except what the team lead needs for the position.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path
Given US-007 lists "Iframe embed : chargée immédiatement (située à 2 100 px du haut de page)" for `https://www.google.com/maps/embed?pb=…`
And the page recorded that document request: `text/html`, 48 ko transferred
When the auditor clicks "embed"
Then a modal opens titled "embed" with the full URL
And it shows "www.google.com", "text/html", "48 ko" and "à 2 100 px du haut de page"
And no iframe is created in the modal

### Scenario 2: Document request not recorded
Given the iframe document was loaded before the recording started
When the auditor opens its modal
Then "Type" reads "inconnu" and "Poids transféré" reads "non mesuré"

### Scenario 3: Keyboard and close
Given the auditor focused the "embed" button
When they press Enter, then Escape
Then the modal opens, then closes, and focus returns to the "embed" button

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Security:** the modal never loads the iframe URL. No request is made.
- **Accessibility:** the same dialog semantics as epic §2.
