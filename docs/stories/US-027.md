# [US-027] Limit the use of canvas elements

> **Epic:** BP3 (see [EPIC-BP3-conventions.md](EPIC-BP3-conventions.md))
> **Rule:** `LimitCanvas`, "Limiter l'utilisation des éléments canvas", category `content`
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-024-027.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each page to report its `<canvas>` elements,
**So that** the site owner checks whether they can be replaced by HTML (or SVG) elements, which avoid script-driven redrawing and stay accessible.

## 2. Context & Detailed Description

### Elements counted

- Every `<canvas>` element in the DOM of the top frame at collection time, displayed or not.
- **Not counted:**
  - `OffscreenCanvas`;
  - canvases created by scripts but never attached to the document, such as fingerprinting or measurement canvases;
  - canvases inside iframes or shadow roots.

### Grade

These are owner decisions.

- **A:** no canvas: "Aucun élément canvas sur la page".
- **B:** one or more: "1 élément canvas : vérifier s'il peut être remplacé par un élément HTML", or "<n> éléments canvas : vérifier s'ils peuvent être remplacés par des éléments HTML" (singular fixed in release 1.0.0).
- There is **no C**.

### Offender lines

- **Format:** `<canvas> : <width> × <height> px`, the CSS box at collection time, rounded.
  - When the element has an `id`: `<canvas id="chart"> : 600 × 400 px`.
  - A canvas whose box is 0 × 0: `<canvas> : non affiché`.
- **Order:** largest displayed area first, then document order; non-displayed canvases come last.
- There is no preview.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** a self-contained `collect()` returning `{ id, width, height }` per canvas, and a pure `evaluate()`.
- **Out of scope:**
  - WebGL detection;
  - animation detection;
  - suggesting the replacement element;
  - canvases in iframes.
- **State:** synchronous.
- **Persistence:** stored with the page.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path
Given the page has no `<canvas>` element
When the best practices are evaluated
Then the rule is graded "A" with the detail "Aucun élément canvas sur la page"

### Scenario 2: One canvas gives B
Given the page has one `<canvas id="chart">` displayed at 600 × 400 px
Then the rule is graded "B" with the detail "1 élément canvas : vérifier s'il peut être remplacé par un élément HTML"
And the line is "<canvas id="chart"> : 600 × 400 px"

### Scenario 3: Many canvases are still B
Given the page has 12 `<canvas>` elements
Then the rule is graded "B" with the detail "12 éléments canvas : vérifier s'ils peuvent être remplacés par des éléments HTML"
And the lines are capped at 20 as usual

### Scenario 4: Hidden canvas
Given the page has a displayed 300 × 150 canvas and a `display: none` canvas
Then both count
And the lines are "<canvas> : 300 × 150 px" then "<canvas> : non affiché"

### Scenario 5: Detached canvases are ignored
Given a script created a canvas with `document.createElement("canvas")` without attaching it
Then it is not counted

### Scenario 6: Collector failure
Given the collector could not run in the page
Then the rule is "Non évaluée" with the detail "La page n'a pas pu être inspectée"

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** collection and evaluation of 200 canvases take under 10 ms.
- **Accessibility:** no new UI.
