# [US-026] Limit the number of CSS files

> **Epic:** BP3 (see [EPIC-BP3-conventions.md](EPIC-BP3-conventions.md))
> **Rule:** `LimitCssFiles`, "Limiter le nombre de fichiers CSS", category `css`
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-024-027.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each page to be graded on how many CSS files it loads,
**So that** the site owner keeps a reasonable split: not dozens of small stylesheets, each a request, and not so few that styles are inlined or bundled into one oversized file.

## 2. Context & Detailed Description

### Files counted

- **A request is a CSS file** when its MIME type is `text/css`, or when the MIME type is missing or generic and the URL path ends with `.css`. This is the same detection as US-008 and US-010 (`textFileType` = `CSS`).
- **Status:** 2xx and `304`. A 304 is a stylesheet the page uses, served from the cache.
- **One per distinct URL** (without fragment), so the same stylesheet requested twice counts once.
- **Included:** stylesheets loaded by `@import`, by scripts, and by third parties.

### Grade

These are owner decisions, exactly as requested, on the number **n** of CSS files.

- **B:** n ≤ 2.
  - n = 0: "Aucun fichier CSS : vérifier que les styles ne sont pas intégrés à la page".
  - n = 1 or 2: "<n> fichier(s) CSS : vérifier que les styles ne sont pas regroupés dans un fichier trop volumineux ou intégrés à la page".
- **A:** 3 ≤ n ≤ 10: "<n> fichiers CSS".
- **C:** n ≥ 11: "<n> fichiers CSS : à regrouper (10 au plus recommandés)".

### Offender lines

- **For C:** every CSS file, as `<display name> : <weight>`, where the weight is the transferred size, or the decoded size when served from the cache, as in US-013. Sorted largest first, then by URL.
- **For B with n ≥ 1:** the same lines, so that the auditor sees the size of the few files.
- **For A:** no lines.
- File names use the US-004 display name. No preview is added in this story.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** a pure `evaluate()` on `RuleContext.requests`, reusing `textFileType`, `lastRequestPerUrl` and the line helpers.
- **Out of scope:**
  - `<style>` blocks (US-024);
  - the unused CSS ratio;
  - the size thresholds of a "too large" file. The B detail only asks the auditor to check.
- **State:** synchronous.
- **Persistence:** stored with the page.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path
Given the page loaded 4 distinct CSS files
When the best practices are evaluated
Then the rule is graded "A" with the detail "4 fichiers CSS" and no lines

### Scenario 2: Boundaries of A
Given the page loaded 3 CSS files
Then the rule is graded "A"
Given the page loaded 10 CSS files
Then the rule is graded "A"

### Scenario 3: Few files give B
Given the page loaded 2 CSS files, "app.css" (180 kB) and "fonts.css" (2 kB)
Then the rule is graded "B" with the detail "2 fichiers CSS : vérifier que les styles ne sont pas regroupés dans un fichier trop volumineux ou intégrés à la page"
And the lines are "app.css : 180 ko" then "fonts.css : 2 ko"

### Scenario 4: No CSS file gives B
Given the page loaded no CSS file
Then the rule is graded "B" with the detail "Aucun fichier CSS : vérifier que les styles ne sont pas intégrés à la page"

### Scenario 5: Boundary, 11 files give C
Given the page loaded 11 distinct CSS files
Then the rule is graded "C" with the detail "11 fichiers CSS : à regrouper (10 au plus recommandés)"
And all 11 files are listed, largest first

### Scenario 6: Duplicates, failures and 304
Given "app.css" was requested twice, "old.css" answered 404, and "theme.css" answered 304
Then "app.css" and "theme.css" count once each, and "old.css" is not counted

### Scenario 7: Detection by extension
Given "/assets/site.css" is served as `application/octet-stream`
Then it counts as a CSS file
And "/style.php" served as `text/css` also counts

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** linear; 2 000 requests in under 10 ms.
- **Accessibility:** no new UI.
