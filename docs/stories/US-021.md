# [US-021] Fewer false positives in "Minifier les fichiers CSS, JavaScript, HTML et SVG"

> **Epic:** BP2 (see [EPIC-BP2-conventions.md](EPIC-BP2-conventions.md))
> **Rule:** `MinifyTextFiles`, "Minifier les fichiers CSS, JavaScript, HTML et SVG", category `network`
> **Changes:** [US-010](US-010.md) §2, "Minification heuristic". The grade, lines, asynchronous behaviour and US-020 preview are otherwise unchanged.
> **Status:** DONE

## 1. User Story Statement

**As an** eco-design auditor,
**I want** the minification rule to flag only files that are clearly not minified,
**So that** its list is credible to the site owner and is not filled with already-minified or negligible files.

## 2. Context & Detailed Description

### Why the current heuristic over-flags

The US-010 heuristic counts comments and every extra whitespace, using a character-level parser that tracks strings and comments.

- **Parser drift:** in minified JavaScript, regular expressions such as `/["']/` are not recognised. They make the parser lose track of strings. A later `"*/*"`, a common `Accept` header value, is then read as the start of a comment, which can swallow tens of kilobytes as "removable".
- **Mid-line runs:** runs of spaces inside strings or aligned code are counted, although they are often meaningful.
- **Tiny files:** a 2 ko file with 5 % whitespace is flagged for 100 bytes, which compression removes almost entirely anyway.
- **Declared builds:** the parser ignores the fact that the file is named `*.min.js`.

### 1. Files declared minified

This is an owner decision.

- A file is **declared minified** when the last segment of its URL **path** ends with `.min.js`, `.min.mjs` or `.min.css`, case-insensitive.
  - The query and fragment are ignored, so `jquery.min.js?ver=3.7.1` is declared.
- A declared file is **counted as evaluated and minified** without reading its content.
  - It is never "non évalué", even when DevTools has no content or the file is over 5 MB.
  - Its content is not read at all, so no content analysis is scheduled for it.
- Files that are **not** declared include `app-min.js`, `app.minified.js`, `min.js`, `app.min.4f3a2c.js` and `style.min.svg`. They are measured as usual.
- The file scope is otherwise unchanged: 2xx, HTML/CSS/JS/SVG, at least 1 000 bytes decoded, and one request per URL.

### 2. Removable characters: whitespace from the line structure only

This is an owner decision.

**Comments are no longer counted.** Strings are no longer tracked, so there is no parser left to drift. Removable characters are only:

| Counted | Definition |
|---|---|
| Line breaks | every `LF` (U+000A) and every `CR` (U+000D); `CRLF` counts 2 |
| Indentation | spaces, tabs and form feeds between the start of a line (start of text, or just after a line break) and its first other character |
| Trailing whitespace | spaces, tabs and form feeds between the last other character of a line and the next line break, or the end of the text |
| Blank lines | a line with only spaces, tabs or form feeds counts entirely, as indentation, plus its line break |

**Not counted:**
- whitespace between two other characters on the same line: `a    b` and `color: red` count 0;
- comments;
- non-breaking spaces and other Unicode spaces.

Whitespace inside multi-line template literals, `<pre>` or `<textarea>` is counted. This is an accepted approximation: in a minified bundle, it is usually indentation of inline templates that could indeed be minified.

Example: `"a {\n    color: red;  \n}\n"` (24 characters) has 9 removable characters: 3 line breaks, 4 of indentation and 2 trailing.

### 3. Flagging threshold

This is an owner decision. A measured file is **not minified** only when **both** of these hold:

- its removable share is **at least 5 %**, as before (`MINIFIED_MAX_REMOVABLE_SHARE`);
- its removable characters are **at least 1 000** (1 ko; removable characters are ASCII, so characters equal bytes).

Otherwise it is minified.

### Unchanged

- The grade (A / B / C / non évaluée) on evaluated files, which now include declared files.
- The detail texts.
- The line format `… : non minifié (~N % d'octets superflus)`, which ARCH-DECISION-024 also recognises on legacy lines.
- The sort order, the "non évalué" lines, the progress state, and the US-020 preview of offender lines.
- **Saved analyses are not re-graded.** Their stored results stay as saved.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:**
  - declared-minified detection;
  - the new whitespace scanner, replacing the comment and string state machine;
  - the 1 000-character floor;
  - the updated tests and fixtures expectations;
  - doc updates (US-010 note, ARCH-DECISION-018 note, README, CHANGELOG).
- **Out of scope:**
  - detecting minification from source maps or bundler banners;
  - counting comments in any form;
  - re-grading saved analyses;
  - `.min.` names other than the three suffixes;
  - changing the wording of lines or details.
- **State:** unchanged (per file `pending | analysed | not-evaluated`); declared files never enter the queue.
- **Persistence:** unchanged; no new persisted field.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path, a declared .min.js is minified without reading it
Given the page loaded "https://cdn.test/jquery.min.js?ver=3.7.1" (90 kB), whose content is indented
When the best practices are evaluated
Then no content analysis is requested for it
And it counts as an evaluated, minified file

### Scenario 2: .min.css and .min.mjs, case-insensitive
Given the page loaded "Bootstrap.MIN.CSS" and "app.min.mjs"
When the best practices are evaluated
Then both count as minified without content analysis

### Scenario 3: Names that are not declarations
Given the page loaded "app-min.js", "app.minified.js", "app.min.4f3a2c.js" and "icon.min.svg", each over 1 000 bytes
When the best practices are evaluated
Then a content analysis is requested for each of them

### Scenario 4: Declared file without captured content, or over 5 MB
Given "vendor.min.js" (6 MB) and "lib.min.js" (no DevTools content) are the only text files of the page
When the best practices are evaluated
Then the rule is graded "A" with the detail "Tous les fichiers CSS, JavaScript, HTML et SVG sont minifiés"
And neither file is listed as "non évalué"

### Scenario 5: An indented file is still flagged
Given "custom.css" (15 kB) has indentation and line breaks making 22 % of its characters
When the best practices are evaluated
Then the line "custom.css (CSS, 15 ko) : non minifié (~22 % d'octets superflus)" is listed

### Scenario 6: Comments are not counted
Given a 20 kB JS file on a single line, half of which is "/* … */" comments
When it is measured
Then its removable characters are 0, or 1 when the file ends with a line break
And it is minified

### Scenario 7: Mid-line whitespace is not counted
Given the text "var a    =    1;"
When it is measured
Then its removable characters are 0

### Scenario 8: Line-structure whitespace is counted
Given the text "a {\n    color: red;  \n}\n"
When it is measured
Then it has 24 characters and 9 removable characters

### Scenario 9: Blank lines and CRLF
Given the text "a\r\n\t\t\r\nb"
When it is measured
Then its removable characters are 6: 4 for the two CRLF and 2 for the blank line's tabs

### Scenario 10: Floor of 1 000 removable characters
Given "icon.svg" of 3 000 characters with 600 removable characters (20 %)
And "theme.css" of 20 000 characters with exactly 1 000 removable characters (5 %)
And "small.css" of 19 980 characters with 999 removable characters (5 %)
When the best practices are evaluated
Then "icon.svg" and "small.css" are minified
And "theme.css" is not minified

### Scenario 11: Reference fixtures still classified
Given the US-010 reference fixtures
When they are measured with the new heuristic
Then "color.min.js", "preflight.min.css" and "app.min.js" are under 5 %
And "color.esm.js", "preflight.css", "page.html" and "design-tool.svg" are at 5 % or more

### Scenario 12: The parser cannot drift any more
Given a single-line minified JS of 50 kB containing `/["']/` followed later by `"*/*"` and `"http://x"`
When it is measured
Then its removable characters are at most 1

### Scenario 13: Chunking invariance
Given any text and any way of splitting it into chunks
When it is fed to the scanner chunk by chunk
Then the result is the same as for the whole text, including a CRLF split across two chunks

### Scenario 14: Saved analyses
Given an analysis saved before this story, with a line "app.min.js (JS, 80 ko) : non minifié (~7 % d'octets superflus)"
When the auditor opens it
Then the stored grade and lines are displayed unchanged, and the line still opens its US-020 preview

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:**
  - The scanner is at least as fast as before: 5 MB in well under 500 ms.
  - The analyser keeps its slicing and yielding.
  - Declared files cost no content read.
- **Accessibility:** no UI change.
