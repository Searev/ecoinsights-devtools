# [US-011] Limit the number of domains serving resources

> **Epic:** BP2 (see [EPIC-BP2-conventions.md](EPIC-BP2-conventions.md))
> **Rule:** `LimitDomains`, "Limiter le nombre de domaines servant les ressources", category `network`
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-006-014.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each page to report how many different domains its resources come from,
**So that** I can flag pages that multiply DNS lookups and connections, and rely on many third parties.

## 2. Context & Detailed Description

### Counting

- **Distinct host names** among the page's `http(s)` requests, including the page's own domain, third parties, iframes and cached responses.
- Each **sub-domain counts separately**, as requested: `www.example.org` and `example.org` are 2 domains, and so are `fonts.googleapis.com` and `fonts.gstatic.com`.
- **Normalisation:** lower case, trailing dot removed, port ignored. IP addresses count as domains.

### Grade

These follow the request exactly.

- **A:** **fewer than 5** domains: "<n> domaine(s)".
- **B:** **exactly 5** domains.
- **C:** **more than 5** domains.

The request also says "at most 5", so 5 is tolerated with a B. The grades above are authoritative.

### Detail and lines

- Detail: "<n> domaines servent les ressources de la page".
- Lines: one per domain, `<domain> : <k> requête(s), <size in ko>` (transferred bytes), sorted by request count, largest first.
- Lines are shown whatever the grade: for this rule they are information, not offenders.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** request URLs and transfer sizes already captured.
- **Out of scope:**
  - grouping by registrable domain (eTLD+1);
  - identifying trackers;
  - DNS timing.
- **State:** synchronous.
- **Persistence:** stored with the page.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: fewer than 5 domains
Given the page requested resources from "example.org", "cdn.example.org" and "fonts.gstatic.com"
When the best practices are evaluated
Then the rule is graded "A" with the detail "3 domaines servent les ressources de la page"

### Scenario 2: Exactly 5 domains gives B
Given the page requested resources from 5 distinct host names
When the best practices are evaluated
Then the rule is graded "B"

### Scenario 3: More than 5 domains gives C
Given the page requested resources from 8 distinct host names
When the best practices are evaluated
Then the rule is graded "C"
And the 8 domains are listed with their request counts, the largest count first

### Scenario 4: Sub-domains count separately
Given requests to "www.example.org" and "example.org"
When the domains are counted
Then they count as 2 domains

### Scenario 5: Normalisation
Given requests to "https://CDN.Example.org:8443/a.js" and "https://cdn.example.org./b.js"
When the domains are counted
Then they count as 1 domain "cdn.example.org"

### Scenario 6: Page with a single request
Given the page made only its document request
When the best practices are evaluated
Then the rule is graded "A" with the detail "1 domaine sert les ressources de la page"

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** linear; 2 000 requests in under 10 ms.
