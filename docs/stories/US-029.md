# [US-029] Offenders indicator for each best practice

> **Epic:** BP-UX (clearer best-practice panels). Sibling story: [US-028](US-028.md) (reference, description, link). Independent of it, but they share `BestPractices.tsx`.
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-028-029.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each best-practice panel to show how many elements break the practice, compared with how many were checked,
**So that** I can see the scale of each problem at a glance and rank what to fix first.

## 2. Context & Detailed Description

### Indicator kinds

These are owner decisions. The indicator always counts **what is wrong**, so a higher number is always worse.

| Kind | Format | Example |
|---|---|---|
| **ratio** | `<offenders> / <expected> <unit> (<p> %)` | `8 / 10 ressources sans cache (80 %)` |
| **count** | `<n> <unit>` | `52 requêtes HTTP` |
| **presence** | `<label> : oui` or `<label> : non` | `CSS print : non` |

- `p` is `round(100 × offenders / expected)`.
- **When `expected` is 0,** a ratio shows `Aucun élément à vérifier`, or the rule-specific wording in the table below.
- Numbers use French digit grouping, as in US-024 to US-027 (`formatCount`).
- Units are singular for 0 and 1, and plural above.

### Per rule

"Offenders" are exactly the elements the rule already flags; "expected" is everything the rule checked. Both come from the rule's own evaluation, so the indicator can never contradict the grade, the detail or the lines.

| Rule | Kind | Offenders / expected (unit) |
|---|---|---|
| `AddCacheHeaders` | ratio | static files whose caching is not allowed / static files checked ("ressources sans cache") |
| `AvoidMediaAutoplay` | ratio | flagged `<video>`/`<audio>` elements / `<video>`/`<audio>` elements checked ("médias en lecture ou chargement automatique") |
| `CompressTextFiles` | ratio | uncompressed text files / text files checked ("fichiers non compressés") |
| `DontResizeImagesInBrowser` | ratio | images resized by the browser / images checked ("images redimensionnées") |
| `ExternalizeCssJs` | count | counted inline blocks ("blocs CSS ou JavaScript en ligne") |
| `LimitCanvas` | count | canvases ("éléments canvas") |
| `LimitCssFiles` | count | CSS files ("fichiers CSS") |
| `LimitDomains` | count | domains ("domaines") |
| `LimitGifs` | count | GIFs of 5 ko or more ("fichiers GIF") |
| `LimitRequests` | count | requests ("requêtes HTTP") |
| `MinifyTextFiles` | ratio | non-minified files / evaluated files, declared ones included, "non évalués" excluded ("fichiers non minifiés") |
| `OptimisedFormats` | ratio | raster images not in an optimised format / raster images checked ("images au format non optimisé") |
| `PreferHttp2` | ratio | HTTP/1 requests / requests with a known protocol ("requêtes HTTP/1") |
| `PrintStyleSheet` | presence | label `CSS print`. Compliance is having one, so `non` is the offending value |
| `ProvideTextAlternatives` | ratio | media without a text alternative / media checked ("contenus sans alternative textuelle") |
| `UseStandardFonts` | count | custom font files loaded ("fichiers de police personnalisés") |
| `UseLazyLoading` | — | no indicator (owner decision: not in the request) |

The team lead checks each rule's current evaluation for the exact sets.
- If a rule doesn't compute its "expected" set today, the rule is extended to compute it, without changing its grade or lines.
- If a definition above conflicts with the rule's logic, the rule's logic wins. The deviation is recorded in the review for owner confirmation.

### Where it is shown

- **Panel header,** right side, before the chevron: the **journey indicator**.
  - **ratio:** offenders and expected are **summed over the pages** where the rule was evaluated, for example `12 / 40 ressources sans cache (30 %)`. A resource on two pages counts twice, consistent with per-page grading.
  - **count:** the **worst page**: `<n> <unit> (page la plus chargée)`. On a single-page analysis there is no suffix.
  - **presence:** `CSS print absente sur <k> page(s) sur <n>`, or `CSS print : oui` when present on all pages, or `CSS print : non` on a single-page analysis without one.
- **"Pages concernées":** each page line ends with its own page indicator, for example `Accueil — 8 / 10 ressources sans cache (80 %)`.
- **States:**
  - While a rule shows progress ("Analyse en cours…", "Estimation en cours…"), no indicator is shown for it.
  - "Non évaluée" pages have no indicator, and they are excluded from the journey sums and the worst page.
  - If no page has an indicator, the header shows none.

### Persistence

- The indicator is computed by the rule at evaluation time and **stored with the page's best-practice result** (`localStorage`): kind, offenders, expected and unit key.
- **Analyses saved before this story** have no stored indicator, so **none is shown**. They are never recomputed.
- A journey mixing old and new pages, which cannot happen in practice, would use the new pages only.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:**
  - an optional persisted `indicator` on `BestPractice`;
  - each rule's `evaluate()` filling it;
  - pure, tested formatting and aggregation helpers in `best-practices-view.ts`;
  - the header and "Pages concernées" rendering;
  - `store-codec` acceptance of the new optional field.
- **Out of scope:**
  - an indicator for `UseLazyLoading`;
  - changing any grade, detail or threshold;
  - charts;
  - sorting panels by indicator;
  - the CSV export.
- **Constraint:** `evaluate()` stays pure and synchronous (ARCH-DECISION-004). The indicator is derived from the same sets the rule already computes, not from a second pass with different filters.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path, ratio on one page
Given a page where 8 of its 10 static files have no caching allowed
When the best practices are evaluated
Then "Ajouter des entêtes Expires ou Cache-Control" shows "8 / 10 ressources sans cache (80 %)" in its header

### Scenario 2: Journey ratio and per-page indicators
Given page 1 has 8/10 files without cache and page 2 has 4/30
When the panel is displayed
Then the header shows "12 / 40 ressources sans cache (30 %)"
And "Pages concernées" shows "8 / 10 ressources sans cache (80 %)" for page 1 and "4 / 30 ressources sans cache (13 %)" for page 2

### Scenario 3: Count, worst page
Given pages with 25, 80 and 41 requests
Then "Limiter le nombre de requêtes HTTP" shows "80 requêtes HTTP (page la plus chargée)" in its header
Given a single-page analysis with 52 requests
Then the header shows "52 requêtes HTTP"

### Scenario 4: Presence
Given a 4-page analysis where 3 pages have no print stylesheet
Then "Fournir une print css" shows "CSS print absente sur 3 pages sur 4"
And each of those pages shows "CSS print : non"

### Scenario 5: Nothing to check
Given a page with no text file in scope for compression
Then "Compresser les fichiers textuels" shows "Aucun élément à vérifier" for that page

### Scenario 6: Pending and non-evaluated
Given "Minifier les fichiers…" shows "Analyse en cours… (2/5 fichiers)"
Then it shows no indicator
Given a page where a DOM rule is "Non évaluée"
Then that page has no indicator and is excluded from the journey sum

### Scenario 7: Minify counts declared files, excludes non-evaluated ones
Given a page with 2 declared ".min.js" files, 3 analysed files of which 1 is non-minified, and 1 "non évalué"
Then the page indicator is "1 / 5 fichiers non minifiés (20 %)"

### Scenario 8: Indicator agrees with the lines
Given any rule with a ratio or count indicator and offender lines
Then the offenders number equals the number of distinct flagged elements, before the 20-line cap

### Scenario 9: Legacy analyses
Given an analysis saved before this story
When the auditor opens it
Then no indicator is shown, and nothing else changes

### Scenario 10: Lazy loading has no indicator
Then "Utiliser le chargement paresseux" shows no indicator

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** each rule's existing 2 000-element budget still holds; aggregation over 50 pages takes under 5 ms.
- **Accessibility:**
  - The header indicator is part of the button's accessible name, after the rule name.
  - Percentages are text, not only colour.
- **Storage:** about 40 bytes more per rule per page, which is acceptable for `localStorage`.
