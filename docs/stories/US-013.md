# [US-013] Limit the use of GIF files

> **Epic:** BP2 (see [EPIC-BP2-conventions.md](EPIC-BP2-conventions.md))
> **Rule:** `LimitGifs`, "Limiter l'utilisation des GIFs animés", category `images`
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-006-014.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each page to report the GIF files it downloads,
**So that** the site owner replaces them with WebM or MP4 videos, which are much lighter for animations, or with modern image formats.

## 2. Context & Detailed Description

### Files counted

This was a product decision: **all GIF files count**, animated or static, as requested. The rule's UI name keeps the wording "GIFs animés" from the request.

- A request is a GIF file when either:
  - its response MIME type is `image/gif`; or
  - the MIME type is missing or generic and its URL path ends with `.gif`, case-insensitive.
- Only 2xx responses are counted.
- Each **distinct URL** (without fragment) counts once per page, so the same GIF requested twice counts once.
- 1 × 1 tracking pixels served as GIF **are counted**. The owner chose to count every GIF.
- **Network-based:** GIFs used as CSS backgrounds or loaded by scripts are included, since the rule reads requests, not the DOM.

### Grade

These follow the request.

- **A:** no GIF: "Aucun fichier GIF".
- **B:** exactly **1** GIF.
- **C:** **more than 1** GIF.

### Offender lines

- Format: `<display name> : <size in ko>` (transferred size).
- Sorted by size, largest first.
- Detail: "<n> fichier(s) GIF : à remplacer par une vidéo WebM ou MP4 pour les animations, ou un format d'image moderne".

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** requests already captured.
- **Out of scope:**
  - detecting animation (frame count);
  - estimating the gain of a WebM conversion;
  - GIFs inside iframes' DOM, though their requests are counted.
- **Overlap:** US-001 and US-002 exclude GIF files, so there is no double reporting with the image rules.
- **State:** synchronous.
- **Persistence:** stored with the page.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: no GIF
Given the page downloaded only JPEG, PNG and WebP images
When the best practices are evaluated
Then the rule is graded "A" with the detail "Aucun fichier GIF"

### Scenario 2: One GIF gives B
Given the page downloaded "loader.gif" (45 kB)
When the best practices are evaluated
Then the rule is graded "B" with the line "loader.gif : 45 ko"

### Scenario 3: More than one GIF gives C
Given the page downloaded "anim.gif" (900 kB) and "pixel.gif" (43 bytes)
When the best practices are evaluated
Then the rule is graded "C"
And "anim.gif" is listed before "pixel.gif"

### Scenario 4: Same GIF requested twice counts once
Given "loader.gif" was requested twice on the page
When the best practices are evaluated
Then it counts as 1 GIF

### Scenario 5: Detection by extension when MIME is generic
Given "/media/banner.gif" is served as `application/octet-stream`
When the best practices are evaluated
Then it counts as a GIF

### Scenario 6: Failed requests are ignored
Given "missing.gif" answered `404`
When the best practices are evaluated
Then it is not counted

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** linear; 2 000 requests in under 10 ms.
