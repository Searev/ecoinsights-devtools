# [US-004] Shortened image file names with the full name on hover

> **Epic:** Image comparison (US-004 → US-005)
> **Builds on:** US-001 and US-002, whose image rules produce per-image findings (`BestPractice.images`)
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-004-005.md`)

## 1. User Story Statement

**As an** eco-design auditor reading the image best practices of a page,
**I want** long image file names to be shortened to a readable, fixed-width form, with the full name available on hover,
**So that** I can scan the list of offending images quickly without long CDN or hashed URLs breaking the layout.

## 2. Context & Detailed Description

The image rules ("Ne pas redimensionner les images dans le navigateur", "Utiliser des formats d'image optimisés") list one line per image. Generated file names (CDN hashes, upload ids) are often over 40 characters and push the gain figures off screen.

### Display name

Every image line shows a **display name** derived from the image URL:

1. **File name:** the last non-empty path segment of the URL, URL-decoded. The query string and fragment are dropped. If decoding fails, the raw segment is used.
   - If the path has no non-empty segment (for example `https://cdn.example.org/` or `https://cdn.example.org/?id=3`), use the **host name**.
2. **Extension:** the part after the **last** dot, when that dot is not the first character and the part is 1 to 5 letters or digits. Otherwise the name has no extension. Its case is kept.
3. **Stem:** the file name without the dot and the extension.
4. **Rule:** this is the product decision, matching the example in the request.
   - Stem ≤ 24 characters: the display name is the full file name, unchanged.
   - Stem > 24 characters: the display name is the **first 12 characters of the stem**, then `...` (three dots), then the **last 12 characters of the stem**, then `.` and the extension when there is one.
   - Characters are counted as Unicode code points, so an emoji or accented character is never split.

| URL (file part) | Display name |
|---|---|
| `962c01_upload-1-c02rkcjxsn76-frame-1-22.jpeg` | `962c01_uploa...6-frame-1-22.jpeg` |
| `photo.jpg` | `photo.jpg` |
| `exactly-twenty-four-char.png` (stem of 24) | `exactly-twenty-four-char.png` |
| `abcdefghijklmnopqrstuvwxyz.webp` (stem of 26) | `abcdefghijkl...opqrstuvwxyz.webp` |
| `a-very-long-file-name-without-any-extension` | `a-very-long-...ny-extension` |
| `archive.tar.gz` | `archive.tar.gz` |
| `photo%20de%20vacances%20%C3%A0%20la%20plage%202024.jpg` | `photo de vac...a plage 2024.jpg` |
| `https://cdn.example.org/?id=3` | `cdn.example.org` |

### Full name on hover

The display name carries the native HTML attribute `title`, set to the **full file name**: decoded, without query string. Hovering shows the browser's native tooltip.

This was a decision. The full URL, including the query string, is shown in the comparison dialog (US-005).

### Where it applies

- The per-image lines of both image rules, in the recording view and in saved analyses.
- The line keeps its other information after the name: resolution, target size, format and gain.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:**
  - a pure, unit-tested `displayImageName(url)` helper;
  - rendering image lines from the structured findings (`BestPractice.images`) instead of the pre-formatted `offenders` strings;
  - the `title` attribute.
- **Out of scope:**
  - other lists (network requests, other rules);
  - the CSV export, which is unchanged;
  - making the name clickable (US-005).

  US-005 turns the name into a button. US-004 must render it as an element that can become one without changing the layout.
- **Legacy analyses:** analyses saved before US-001 have only `offenders` strings and no `images`. They keep their current display, with no shortening and no tooltip.
- **State:** none. The display is a pure derivation of the persisted findings.
- **Persistence:** none. The stored data is unchanged.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: long hashed name is shortened
Given an image finding for "https://cdn.example.org/img/962c01_upload-1-c02rkcjxsn76-frame-1-22.jpeg"
When the image line is displayed
Then the visible name is "962c01_uploa...6-frame-1-22.jpeg"
And its "title" attribute is "962c01_upload-1-c02rkcjxsn76-frame-1-22.jpeg"

### Scenario 2: Short name is unchanged
Given an image finding for "https://example.org/photo.jpg?v=3"
When the image line is displayed
Then the visible name is "photo.jpg"
And its "title" attribute is "photo.jpg"

### Scenario 3: Boundary: stems of 24 and 25 characters
Given a file name whose stem is <length> characters long with the extension "png"
When the display name is computed
Then the stem is <outcome>

Examples:
| length | outcome |
| 24     | kept in full |
| 25     | shortened to 12 + "..." + 12 |

### Scenario 4: Name without extension
Given an image finding for "https://example.org/media/a-very-long-file-name-without-any-extension"
When the display name is computed
Then the visible name is "a-very-long-...ny-extension"

### Scenario 5: Encoded characters
Given an image finding whose file part is "photo%20de%20vacances%20%C3%A0%20la%20plage%202024.jpg"
When the display name is computed
Then the visible name is "photo de vac...a plage 2024.jpg"
And the "title" attribute is "photo de vacances à la plage 2024.jpg"

### Scenario 6: Malformed encoding
Given an image finding whose file part is "bad%E0%A4%A.jpg"
When the display name is computed
Then the raw segment "bad%E0%A4%A.jpg" is used and no error is raised

### Scenario 7: URL without a file segment
Given an image finding for "https://cdn.example.org/?id=3"
When the display name is computed
Then the visible name is "cdn.example.org"

### Scenario 8: Unicode is never split
Given a file name whose 12th and 13th code points form an emoji
When the display name is computed
Then the emoji appears whole or not at all, never as a broken character

### Scenario 9: Legacy saved analysis
Given an analysis saved before US-001, with offender strings and no image findings
When its best practices are displayed
Then the offender lines are displayed exactly as before

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Accessibility:**
  - the full file name must be available to assistive technologies, not only through `title`, which screen readers announce inconsistently;
  - the shortened text must not be the only accessible name (`aria-label` or visually hidden text with the full name);
  - layout: a name never wraps on two lines in the default panel width.
- **Performance:** the helper is pure and O(n) in the name length. Rendering 300 lines adds no measurable delay.
