# [US-009] Add Expires or Cache-Control headers to static files

> **Epic:** BP2 (see [EPIC-BP2-conventions.md](EPIC-BP2-conventions.md))
> **Rule:** `AddCacheHeaders`, "Ajouter des entêtes Expires ou Cache-Control", category `network`
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-006-014.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each page to report the static files served without HTTP caching,
**So that** returning visitors and later pages reuse them from the browser cache instead of downloading them again.

## 2. Context & Detailed Description

### Static files

A request of the page is a static file when either:

1. its URL **path**, ignoring the query string, ends with one of these extensions, case-insensitive:

   `xml ogg ogv svg svgz eot otf woff woff2 mp4 ttf css rss atom js mjs jpg jpeg gif png ico zip tgz gz rar bz2 doc xls exe ppt tar mid midi wav bmp rtf webp avif webm mp3 m4a`

   This is the list from the request, plus `woff2`, `mjs`, `mp3` and `m4a`, a product decision; or
2. its path has **no extension**, and its MIME type is one of:
   - `image/*`, `font/*`, `audio/*`, `video/*`;
   - `text/css`, a JavaScript type;
   - `application/font-*`, `application/x-font-*`;
   - `application/zip`, `application/gzip`, `application/xml`, `application/rss+xml`, `application/atom+xml`.

Only 2xx and `304` responses are checked. A 304 carries the cache headers of the stored resource.

### Caching allowed

This was a product decision: having a header is not enough, it must allow caching. A static file is **compliant** when its response headers allow the browser to reuse it:

1. **`Cache-Control` takes precedence when present.**
   - **Not compliant** if it contains `no-store`, `no-cache` or `max-age=0`.
   - **Compliant** if it contains `max-age=N` with N > 0, or `immutable`.
   - Otherwise, it falls back to `Expires`.
   - `s-maxage` is ignored, because it only applies to shared caches.
2. **`Expires`:** compliant if it is a valid HTTP date **later than** the response `Date` header, or later than the request time when `Date` is missing.
   - Invalid dates and `Expires: 0` are not compliant.
3. **Neither header:** not compliant.

### Grade

These follow the request; the worst grade wins.

- **C:** there is at least one static file and **none** is compliant.
- **B:** at least one static file is not compliant, but not all.
- **A:** all are compliant, or the page has no static file: "Tous les fichiers statiques peuvent être mis en cache".

### Offender lines

- Format: `<display name> : <reason>`.
- Reasons:
  - "aucune entête de cache";
  - "Cache-Control: no-store";
  - "Cache-Control: no-cache";
  - "max-age=0";
  - "Expires dans le passé";
  - "Expires invalide".

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** response headers already captured (`responseHeaders`, `type`, `code`, `url`).
- **Out of scope:**
  - `ETag` and `Last-Modified` (validation, not caching);
  - judging whether a duration is long enough;
  - `Vary`;
  - service-worker caches.
- **Edge:** a duplicated header in the recorded data is joined with ", " by the normaliser, so directives are parsed from the comma-separated list.
- **State:** synchronous.
- **Persistence:** stored with the page.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: all static files cacheable
Given "app.js" has `cache-control: public, max-age=31536000, immutable` and "logo.png" has an `expires` one year after its `date`
When the best practices are evaluated
Then the rule is graded "A"

### Scenario 2: Some files without caching give B
Given "style.css" has `cache-control: max-age=3600`
And "font.woff2" has no `cache-control` and no `expires`
When the best practices are evaluated
Then the rule is graded "B"
And the line "font.woff2 : aucune entête de cache" is listed

### Scenario 3: No static file cacheable gives C
Given the page loaded 3 static files and none has a compliant header
When the best practices are evaluated
Then the rule is graded "C"

### Scenario 4: Headers that forbid caching are not compliant
Given static files with `cache-control: no-store`, `cache-control: no-cache` and `cache-control: max-age=0`
When the best practices are evaluated
Then each is listed with its reason

### Scenario 5: Cache-Control takes precedence over Expires
Given a static file with `cache-control: no-cache` and an `expires` date in the future
When the best practices are evaluated
Then it is not compliant with the reason "Cache-Control: no-cache"

### Scenario 6: Expires in the past or invalid
Given one static file with `expires` earlier than its `date`, and another with `expires: 0`
When the best practices are evaluated
Then they are listed as "Expires dans le passé" and "Expires invalide"

### Scenario 7: Static file without extension detected by MIME
Given "/fonts/roboto?family=Roboto" is served as `font/woff2` with no cache header
When the best practices are evaluated
Then it is checked as a static file and listed

### Scenario 8: HTML pages are not static files
Given the document "/index.html" has no cache header
When the best practices are evaluated
Then it is not checked, because html is not in the list

### Scenario 9: 304 response carries the stored headers
Given "app.js" answered `304` with `cache-control: max-age=600`
When the best practices are evaluated
Then it is checked and compliant

### Scenario 10: Page without static files
Given a page whose only requests are the HTML document and JSON API calls
When the best practices are evaluated
Then the rule is graded "A" with the detail "Tous les fichiers statiques peuvent être mis en cache"

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Performance:** linear; 2 000 requests in under 10 ms.
- **Robustness:** header parsing never throws on malformed values; a malformed value counts as not compliant.
