# [US-007] Use lazy loading

> **Epic:** BP2 (see [EPIC-BP2-conventions.md](EPIC-BP2-conventions.md))
> **Rule:** `UseLazyLoading`, "Utiliser le chargement paresseux", category `images`
> **Status:** DONE (automated gates passed, manual browser checks pending; see `docs/reviews/REVIEW-US-006-014.md`)

## 1. User Story Statement

**As an** eco-design auditor,
**I want** each page to report the images and iframes below the first screen that are loaded immediately instead of lazily,
**So that** visitors who never scroll that far don't download them.

## 2. Context & Detailed Description

### Elements checked

- `<img>` and `<iframe>` are the only elements supporting the `loading` attribute. An `<img>` inside a `<picture>` is counted once.
- **Above the fold, excluded.** This was a product decision. An element whose top edge, in document coordinates (`getBoundingClientRect().top + scrollY`), is above the viewport height (`innerHeight`) is visible on arrival. It must **not** be lazy, because lazy-loading the main visible image delays it (LCP). These elements are neither offenders nor counted.
  - Using document coordinates makes the result independent of the current scroll position.
- **Also excluded:**
  - elements not rendered (0 × 0 box, `display:none`);
  - images whose `src` is a `data:` URI;
  - tracking pixels (natural size ≤ 1 × 1).

### Compliance per element below the fold

- **Lazy:** `loading="lazy"`, case-insensitive.
- **Lazy through a script:** this is a PO default.
  - Condition: an `<img>` that has a `data-src` or `data-srcset` attribute, and whose `src` is empty or not yet loaded (`complete` with a natural width of 0, or a `data:` placeholder).
  - Reason: lazy-loading libraries such as lazysizes defer it.
- **Not lazy:** anything else, including `loading="eager"` or no attribute.

### Grade

These follow the request.

- **A:** every checked element is lazy, or there is none: "Aucune image ni iframe hors de l'écran initial chargée immédiatement".
- **B:** exactly **one** element is not lazy.
- **C:** **more than one** element is not lazy.

### Offender lines

- Format: `<display name> : chargée immédiatement (située à <n> px du haut de page)`.
- Iframes use their `src` display name, prefixed with "Iframe ".
- Sorted by distance from the top of the page.

## 3. Tech Stack Hints & Scope Constraints

- **In scope:** `img` and `iframe` in the top-frame DOM; the above-the-fold exclusion; script lazy-loading detection.
- **Out of scope:**
  - CSS background images;
  - `<video>` preload (US-014);
  - the `fetchpriority` attribute;
  - iframes' own content.
- **Timing:** collection happens at the existing moments (page start, significant DOM change, before closing).
  - An element that becomes lazy-loaded later is judged on its state at the latest collection.
  - The viewport height is that of the inspected tab at collection time.
- **State:** synchronous; no loading state.
- **Persistence:** stored with the page.

## 4. Acceptance Criteria (Gherkin Scenarios)

### Scenario 1: Happy path: below-the-fold images are lazy
Given a viewport of 800 px height
And images at 1 200 px and 2 400 px from the top of the page with `loading="lazy"`
When the best practices are evaluated
Then the rule is graded "A"

### Scenario 2: Above-the-fold image is not required to be lazy
Given a viewport of 800 px height
And a hero image at 100 px from the top without `loading`
When the best practices are evaluated
Then the hero image is not listed and does not affect the grade

### Scenario 3: One eager image below the fold gives B
Given exactly one image below the fold without `loading="lazy"`
When the best practices are evaluated
Then the rule is graded "B"
And the line "<name> : chargée immédiatement (située à 1 500 px du haut de page)" is listed

### Scenario 4: Two eager elements below the fold give C
Given one image and one iframe below the fold, both without `loading="lazy"`
When the best practices are evaluated
Then the rule is graded "C"
And both lines are listed, the iframe prefixed with "Iframe "

### Scenario 5: Independent of the scroll position
Given an image at 1 500 px from the top without `loading="lazy"`
And the auditor has scrolled so that the image is currently visible
When the best practices are evaluated
Then the image is still considered below the fold and listed

### Scenario 6: Script-based lazy loading
Given an image below the fold with `data-src="photo.jpg"` and an empty `src`
When the best practices are evaluated
Then it is considered lazy and not listed

### Scenario 7: Hidden, data-URI and tracking-pixel images are ignored
Given below-the-fold images that are `display:none`, have a `data:` src, or are 1×1
When the best practices are evaluated
Then none of them are listed or counted

### Scenario 8: Page without images or iframes
Given a page with no `img` or `iframe`
When the best practices are evaluated
Then the rule is graded "A" with the detail "Aucune image ni iframe hors de l'écran initial chargée immédiatement"

### Scenario 9: Element straddling the fold
Given a viewport of 800 px height and an image whose top edge is at 790 px
When the best practices are evaluated
Then the image is above the fold, not listed, because its top edge is within the viewport

## 5. Non-Functional Requirements (NFRs) & Constraints

- **Self-contained collector:** it passes the registry serialisation test.
